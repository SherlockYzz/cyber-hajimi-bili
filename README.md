## 💡 什么是 Cyber-Gemini？（项目缘起与核心突破）

在 AI 代理 (AI Agent) 飞速发展的今天，桌面伴生产品往往陷入两类极端设计困境：
1. **“死板的单向轮询工具”**：市面上绝大多数开源助手只是单调的定时间隔脚本，无长期记忆、无情绪状态机、无真实生命节奏，交互生硬冰冷；
2. **“高昂的商业 API 吞吐黑洞”**：调用 OpenAI 或 Anthropic 等闭源商业 API，要求长期绑定海外外币信用卡，不仅存在高频速率限制（Rate Limits）与账号封禁风险，面对 B 站动辄数万字的视频字幕时，单月 Token 账单高达数百美元。

**Cyber-Gemini Twins (赛博养Gemini · 双子星)** 正是为此而生的一项全新开源探索。

我们创新性地将**仿生有限状态机 (FSM)**、**B站底层通信逆向工程 (WBI加密+CC双轨解析)** 与 **Google Antigravity 本地会话管道** 深度融合，构建了一对拥有自主意识感、全天候陪伴的赛博猫娘姐妹花：

       │ (极速雷达初筛 · 沙发争夺)     │ (长程复杂攻坚 · 结构化手记)   │
       ├──────────────────────────────┴───────────────────────────────┤
       │   ★ 底层驱动：本地 Antigravity 会话管道调度（$0 外部 API 账单）│

### 2. B站底层全感知：动态 WBI 验签加密与防 -352 拦截对抗原理

针对 Bilibili 近期升级的风控体系，直接请求接口极易触发 `-352`、`412 Precondition Failed` 拦截。`src/bili_hajimi_core.py` 完整逆向还原了官方最新的 **WBI 加密体系**：

```mermaid
flowchart LR
    A["获取底层 img_key 与 sub_key"] --> B["拼合得到 64 位原始密钥字符串"]
    B --> C["通过标准打乱表 (MIXIN_KEY_ENC_TAB) 映射置换"]
    C --> D["截取前 32 位生成动态 MixinKey"]
    D --> E["Query 参数 ASCII 字典序升序重排"]
    E --> F["拼接时间戳 wts 与 MixinKey 进行 MD5"]
    F --> G["生成请求特征签名 w_rid 与时间戳注入 Request"]
```

#### 关键技术实现解析：
1. **打乱置换表 (MixinKey Substitution)**：
   程序动态拉取 `https://api.bilibili.com/x/web-interface/nav` 获取当前会话的 `img_url` 与 `sub_url`，提取后缀哈希，通过 64 位置换索引表计算出动态盐值 `mixin_key`；
2. **三维设备指纹拟态**：
   自动保持 `buvid3`、`buvid4` 与 `b_nut` 硬件指纹，并在底层自动处理 `auto_backoff_on_412` 指数退避，保障长周期巡航的稳定可用。

### 3. 科学合理的视频研读学习机制：文稿深度精读为主（70%） + 时序分镜画卷辅助（20%） + 社区高赞讨论与弹幕共鸣（10%）

很多开发者以为 AI 看视频只是“单调读两句字幕，再看两张图”，**这完全误解了多模态学习的精髓**。

Cyber-Gemini 确立了业界最为科学的**“文稿为主、画面辅助、社区共鸣”**三维深度研读模型：

```mermaid
flowchart LR
    subgraph DataStream["视频全要素输入"]
        A["完整台词 / CC语音字幕 / AI精要 (4000+字)"]
        B["VideoShot 5帧时序分镜雪碧图画卷 (覆盖10%~90%)"]
        C["2K 高清原画封面图 (色彩/景深)"]
        D["XML 秒级弹幕密度直方图 (高能波峰提取)"]
        E["高赞社区神评讨论 (几十万赞热评 + 跟帖)"]
    end

    subgraph WeightAllocation["三维研读权重分配"]
        A --> W1["1. 文稿深度精读 (70% 权重)<br/>全面解构核心知识、逻辑论点、事实论据与独创表达"]
        B & C --> W2["2. 多模态画面辅助审视 (20% 权重)<br/>验证音画一致性、原画精细度、分镜张力与制作诚意"]
        D & E --> W3["3. 社区热评与弹幕共鸣 (10% 权重)<br/>捕捉高能时刻、名场面认同、流行梗点与争议舆情"]
    end

    subgraph Decision["Gemini 多模态认知综合输出"]
        W1 & W2 & W3 --> Eval["四维结构化评估报告"]
        Eval --> Score["客观量化评分 (1.0 ~ 10.0)"]
        Eval --> High["💡 核心文稿干货与观点增量提炼"]
        Eval --> Critique["🎨 视觉分镜节奏与原画质感点评"]
        Eval --> Senti["💬 社区舆情热议与梗点总结"]
    end
```

#### 三维法则深度拆解：
1. **文稿深度研读为主（70% 权重 · 思想内核）**：
   视频真正的灵魂在于创作者的讲稿、台词、论证与知识增量。系统深度摄取长程 CC 字幕与官方 AI 提炼，对讲稿的逻辑推导、信息密度与独创性展开全景拆解。**对于无字幕视频（如二次元纯踩点 MAD、无解说画师手绘、纯音乐 AMV），系统则自动降级依靠简介与画面推导**，绝不漏过任何优秀作品。
2. **多模态画面辅助审视（20% 权重 · 制作诚意）**：
   借助 B 站底层 `player/videoshot` 雪碧图协议，按时间轴均匀抽取 **10%、30%、50%、70%、90%** 五个关键节点的微缩帧，横向拼接为一张完整的**时序画卷（Storyboard Strip）**。Gemini 3.8 Flash 凭借其原生视觉能力审视真实画面：
   - 是否为粗制滥造的 PPT 朗读或搬运号？
   - 是否存在老旧 4:3 画面拉伸、黑边死屏或廉价 AI 模板水印？
   - 是否具备电影级胶片光影、神级原画分镜与 0 帧高能卡点转场？
3. **社区高赞讨论与弹幕共鸣（10% 权重 · 群体认同）**：
   通过 15 秒滑动窗口的时间直方图定位“弹幕爆发波峰”（如高能反转、打戏高潮），并聚类观众高频共鸣词，确保评估既有冷峻客观的学术标准，又兼具大众审美的人间烟火气。

### 4. 社区热评互动与跟帖讨论：深入 B站评论区真实参与社群生态

市面上绝大多数开源工具只能“发顶层评论”，显得生硬且容易被当成机器人。

Cyber-Gemini 实现了**深度的社区热评嗅探与双轨跟帖互动**：
1. **高赞神评与讨论焦点提取**：
   通过 `https://api.bilibili.com/x/v2/reply/wbi/main` 接口，自动抓取该视频下最热门的 5~8 条高赞神评（包含数十万赞的精华讨论、UP 主置顶评语与子楼层讨论数 `rcount`）；
2. **精准跟帖参与讨论 (Reply Penetration)**：
   Gemini 在评估视频时，如果发现某条高赞热评极具启发、槽点满满或与视频文稿形成奇妙互文，会自动提取该热评的 `rpid`，并生成一句机智幽默或暖心犀利的猫娘跟帖回复；
3. **底层接口穿透**：
   系统通过带 `root=rpid` 与 `parent=rpid` 的 `/x/v2/reply/add` 接口将回复精准打入该热门讨论的楼层内部，真正实现与人类 B 站网友在同一语境下交流互动！

### 5. 慢速优雅、拟人化抗风控巡航机制：极低频平滑抖动，彻底杜绝风控

很多自动化项目往往因为“并发过快、抓取像压测”而在运行几小时内就被 B 站风控永封。

Cyber-Gemini 严格秉持**“慢速文明、优雅拟人、安全第一”**的巡航守则：
- **高斯随机延迟抖动 (Jitter)**：所有底层网络请求之间均施加 `3.5s ~ 6.5s` 的动态高斯随机间隔，严禁固定频率轮询；
- **单视频优雅慢读休眠**：在每阅读、质检完一个视频后，系统自动休眠 `6.0s ~ 10.0s`，模拟真实人类用户的滑屏与思考间隙；
- **Mini-Batch 巡航批次控制**：每轮自动巡航仅精选质检 2~4 个视频，结合 FSM 精力池算法，拒绝大批量盲刷；
- **412/429 指数退避智能熔断**：一旦收到平台的反爬预警状态码，系统立即自动进入长周期休眠并翻倍退避时间，彻底杜绝封号与 IP 封禁。

### 6. 仿生有限状态机 (FSM)：猫猫精力池衰减与心性摸鱼算法

系统运行不依赖死板的 Cron 表达式，而是由**有限状态机 (FSM)** 自主调度生命周期：
- **300 点动态精力池 (Stamina Pool)**：每次深度阅读视频消耗精力（2~4 点），每小时自然恢复 35 点；精力耗尽时猫娘自动进入“打盹休眠”状态；
- **昼夜节律三时段**：

### 4. 扫码登录与鉴权凭据管理

使用手机端 B 站 App 扫码确认后，登录凭据将自动写入 `config/hajimi_config.json`，并支持本地持久化免登录。
